F01 [P1，已复现] RSA 私钥销毁无效
位置：cryptography/lib/src/cryptography/rsa_key_pair.dart:96、117、134。
hasBeenDestroyed 恒为 false，继承 destroy() 改变的状态被遮蔽；d/p/q 等为普通 List。
复现：destroy() 后状态仍为 false，d 仍可读取，extract() 仍成功。
影响：调用者以为已撤销/清除的私钥仍可使用；copy() 也共享原始数组。
建议：私密参数采用独立敏感缓冲区，正确实现销毁、复制和访问状态；保留公开参数访问。

F02 [P1，已复现] EC copy() 与原私钥共享生命周期
位置：cryptography/lib/src/cryptography/ec_key_pair.dart:124。
copy() 把 d getter 返回的 SensitiveBytes 直接传给新对象，形成嵌套包装。
复现：copy = original.copy(); original.destroy(); 此后读取 copy.d 抛异常。
影响：副本不独立，销毁原对象会让仍使用中的副本失效，副本状态还可能不准确。
建议：复制私钥字节，并测试双向销毁互不影响。

F03 [P2，已复现，现有测试失败] SecretKeyData 相等比较不对称并抛异常
位置：cryptography/lib/src/cryptography/secret_key.dart:177。
只检查 this.hasBeenDestroyed，随后读取 other.bytes。
复现：live == destroyed 抛 StateError；destroyed == live 返回 false。
影响：普通比较及集合/测试匹配可能异常；VM/JS/WASM 均失败。
建议：比较前检查双方销毁状态，明确相等和 hash 的约定，并补充两种比较顺序测试。

F04 [P1，已复现] JWK 与标准字段格式不兼容
位置：jwk/lib/jwk.dart:119、140、472、515、542、641。
key_ops 被建模为 String，标准要求字符串数组；x5c 被建模为单段 bytes 并 base64url 编码，标准要求普通 base64 证书字符串数组；对称密钥使用大写 OCT，标准为小写 oct。
复现：标准 key_ops/x5c 数组发生类型错误；kty=oct 的 toSecretKey() 抛 StateError。
影响：与外部 JWKS/JOSE 实现互通失败。
建议：按 RFC 7517/7518 修正类型、编码与大小写，考虑兼容读取旧 OCT 格式；该项可能涉及公开 API 变更。
参考：https://www.rfc-editor.org/rfc/rfc7517.html#section-4.3
https://www.rfc-editor.org/rfc/rfc7517.html#section-4.7
https://www.rfc-editor.org/rfc/rfc7518.html#section-6.4
